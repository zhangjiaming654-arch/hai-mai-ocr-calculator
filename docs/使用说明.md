# 海迈取数计算器 · 使用说明

## 用途

在计价软件的「相同清单编制」界面里，框住屏幕上的数字，按你设定的下浮率，算出该填的价：

| 模式 | 框住什么 | 输出什么 |
|---|---|---|
| **主材单价** | 「控制单价」一个数 | 该填的**主材单价** |
| **调价** | 「控制单价」+「单价下浮」两个数（从左到右） | 「调整人材机」里该填的**定额系数** |

两种模式共用一个「下浮率」输入框。

## 怎么用（三步）

1. 双击桌面上的「海迈取数计算器」（蓝底虚线框 + ¥ 图标），或双击文件夹里的 `run.bat`。
   小窗口总在所有窗口上面。
2. 把窗口拖到计价软件表格上，**拖窗口里的蓝色取景框**对准要取的数字：
   - 拖蓝框的四个角 = 把框放大/缩小（可以缩到只剩一行、只框一列）
   - 拖蓝框的边框 = 整个框挪位置
   - 框外那层点状灰 = 「这一块不取」
   - 框里面是**真透明** = 数字看得清清楚楚，不会看错行（所以框内鼠标点不进去，挪框请拖边框）
3. 选好模式，点【识别】→ 结果框里只显示一个数。改下浮率会立即重算，不用重新识别。
   **结果会自动进剪贴板**：到计价软件里按 `Ctrl+V` 直接粘贴（多行时一次粘多行），关掉本窗口后也还能粘。

模式、窗口大小、取景框的位置和大小都会被记住；切换模式时取景框自动换成该模式的默认大小
（主材单价 80×48，调价 140×53），你也可以随时再拖。

## 下浮率怎么填（符号跟海迈一样）

| 你填 | 含义 | 海迈「单价下浮」列 |
|---|---|---|
| `−9` | 下浮 9% | −9 |
| `−9.68` | 下浮 9.68% | −9.68 |
| `9` | 上浮 9% | +9 |
| `0` | 不下浮 | 0 |

```
目标单价 = 控制单价 × (1 + 下浮率 ÷ 100)
```

## 两种模式的计算

### 主材单价模式

适用于「定额里只有主材、没有别的人材机」的情况：

```
综合单价 = 主材单价 × K
K        = (1+管理费率) × (1+利润率) × (1+税率)
         = 1.0679 × 1.06 × 1.09 = 1.23385166      （本工程取费口径）

主材单价 = 目标单价 ÷ K
```

例：控制单价 245.89，填 −9.68 → 目标单价 222.09 → 主材 180.00。

> 为什么是连乘放大：这套口径的**取费基数 = 人工费 + 材料费 + 机械费**，
> 主材（材料费）被管理费、利润、税金各乘一次，所以被放大 23.39%。
> 换工程改 `config.json` 里的 `mgmt_rate` / `profit_rate` / `tax_rate`。

### 调价模式

「调整人材机」填的是**定额系数**，对定额人材机等比放大，综合单价是线性的：

```
系数 = (1 + 目标下浮率/100) ÷ (1 + 当前下浮率/100)
```

例：控制单价 982.33、当前下浮 −36.94%、目标 −9%
→ `0.91 ÷ 0.6306 = 1.443`，在「定额 系数」里填 **1.443**。
（填 1.44 得 −9.19%，填 1.45 得 −8.56%。）

调价模式只用到两个下浮率，**与取费口径无关**，所以定额里还有人工/铁件/机械时用这个更准。

## 随机模式（可选，默认关）

勾选「随机数」后，每点一次【识别】，输出的数会在设定下浮率上下 **0.25 个百分点以内**重新随机一次；
反算出来的实际下浮率仍落在 ±0.25% 带内（程序逐行校验，不满足就重摇，最多 40 次）。

- 用途：一批清单连着填时，数值不会一直是同一个，更像逐条组价。
- 勾选状态会被记住（`config.json` 的 `rand_mode`）。
- 关掉即恢复精确值：`245.89 @ −9.68% → 180.00`。
- 调价模式随机时系数给 **3 位小数**：2 位小数下系数动 0.01，下浮率会跳 0.6~0.9 个百分点，落不进 ±0.25%。

实测（本机 2026-11-08，20 次连摇）：主材 17 个不同值、最大偏差 0.2386 个百分点；调价 6 个不同值、最大偏差 0.2284 个百分点；全部在带内。

## 小数（可选，默认勾上）

| 勾选状态 | 主材单价模式 | 调价模式 |
|---|---|---|
| 勾上（默认） | `180.00`（2 位） | `1.01`（2 位；随机开启时 3 位） |
| 取消 | `180`（整数） | `1`（整数） |

- 勾选状态会被记住（`config.json` 的 `decimals`）。
- 取消小数后，整数取整会带来约 0.5% 的跳跃（主材每 1 元 ≈ 0.5 个百分点），
  随机数的 ±0.25% 难以严格满足，程序会自动挑偏差最小的那个值。

## 费率要改怎么办

用记事本打开 `config.json`，改 `mgmt_rate` / `profit_rate` / `tax_rate`（单位 %），存盘重开。
程序启动时会自检（245.89 填 −9.68 应得 180.00，且正数结果要比负数大），对不上会弹窗提醒。

## 小提示

- 取景框内透明穿透，挪框请拖边框、改大小拖四个角。
- 只认**大于 1 的正数**：负数（下浮率那种 −9.68）和合计列的杂讯会丢掉——下浮率请在输入框里填。
- 计价软件窗口必须真的显示在屏幕上（被别的窗口挡住、最小化都识别不到）。
- 框到多行会输出多行（每行一个结果）。
- 万一出错，日志在 `%TEMP%\hm_app.log`。
- `ocr_serve.ps1` 是常驻 OCR 服务，第一次识别时自动拉起，别删。

### 2026-11-09　修复"一个数被识别成两个数"

- **症状**：框住 `1218.59`，结果区却输出两行（对应被认成 `121` 和 `59`）。
- **原因**：Windows OCR 对这类字体的 `8.` 会读飘（`1218.59` → `121 & 59`）；另外旧逻辑把行内空格一律删掉，相邻两格的数字会被粘成一个数（`1218 ， 59 40` → `1218.594`）。
- **修法**：
  1. 空格不再一律删除：只有紧挨小数点/负号的空格算"数字内部"，其余空格作为数字分隔，避免跨格粘连；
  2. 用模式当校验：主材单价模式期望 **1** 个数、调价模式期望 **2** 个数，依次尝试多组预处理（阈值 120/140/160/100 + 原图），取个数正好匹配的那一次；
  3. 兜底：个数对不上时，主材模式取最像单价的数、调价模式取最靠左两个；
  4. 顺带修掉临时图片复用导致的 `Errno 22`（每次换新文件名）。
- **实测**：`1218.59` → 单个数，结果 `799.98`；`245.89` → `180.00`；调价 `245.89 / −9.68`、目标 −9 → `1.01`。

### 2026-11-09　修复"大数被当成噪音丢掉"

- 症状：框住 `382567.6  -84.23`（调价模式），提示"没认出数字"。
- 原因：解析时把 0.01 ~ 99999.99 以外的数当噪音过滤掉，38 万这种六位数直接没了，只剩 `-84.23` 一个数，
  而调价模式要两个数，于是一路判定"没认出"。
- 修法：上限放宽到 10 亿；另外框里多框到第三个数（如合价）时，仍按"从左往右取前两个"的规则。
- 实测：该组数字现在识别为 `[382567.6, -84.23]`，目标 −9% → 系数 `5.77`。

### 2026-11-09　新增「小数」勾选框

- 取消小数时整数取整会带来约 0.5% 的跳跃，随机模式的 ±0.25% 无法严格满足，程序自动挑偏差最小的值。
